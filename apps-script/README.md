# 研究DB（Googleスプレッドシート）自動入力のセットアップ

evaluation.html（大腿骨近位部骨折 研究評価記録）から、運動器データベースの
スプレッドシートへ評価記録を自動入力するための手順です。
一度セットアップすれば、以降は「DB送信」タブの「整合性を確認して送信」ボタンだけで転記できます。

## 仕組み

```
evaluation.html（GitHub Pages）「DB送信」タブ
        │  ① GET ?action=roster … 登録済み ID⇔氏名 の対応表を取得
        │  ② 連結匿名化の整合性チェック（H番号と氏名の対応を照合）
        │  ③ fetch(POST, JSON) … チェックOKのときだけ送信
        ▼
Google Apps Script ウェブアプリ（doGet / doPost）
        │  ID + time_point をキーに upsert
        ▼
運動器データベース（Googleスプレッドシート・大腿骨シート）
```

- 送信前に必ず連結匿名化の整合性チェックが走ります:
  - 入力中のID（H番号）がDB登録済み → 氏名が一致しなければ**送信中止**
  - IDが未登録なのに同じ氏名が別IDで登録済み → **送信中止**（重複登録防止）
  - 完全に新規のID → 確認ダイアログの後に登録
- 同じ「ID + 評価時期」を再送信すると、同じ行が上書きされます（重複行はできません）。
- **空欄の項目は送信されません**。シートの既存値が空欄で上書きされることはないため、
  値を消したい場合はシート側で直接削除してください。
- CCI・SMI・Pha・歯の変数・Alb・TLA・入棟日/退院日などシート専用の列は、
  アプリの「DB送信」タブに入力欄があります。

## セットアップ手順（初回のみ・約10分）

### 1. xlsx を Google スプレッドシート形式に変換する

現在のデータベース「運動器_20260519.xlsx」は **Excel形式のままDriveに置かれているため、
Apps Script から書き込めません**。先にネイティブのスプレッドシートに変換します。

1. Google ドライブで「運動器_20260519.xlsx」を開く
2. メニューの「ファイル」→「Google スプレッドシートとして保存」
3. 以降はこの変換後のファイルを正としてください（xlsx側は更新されません）

### 2. Apps Script を設定する

1. 変換後のスプレッドシートを開き、「拡張機能」→「Apps Script」
2. エディタに `Code.gs` の内容を全部貼り付けて保存
3. シート名が「大腿骨」でない場合は、冒頭の `SHEET_NAME` を実際のタブ名に合わせる

### 3. ウェブアプリとしてデプロイする

1. Apps Script エディタ右上の「デプロイ」→「新しいデプロイ」
2. 種類の選択（歯車アイコン）→「ウェブアプリ」
3. 設定:
   - 説明: 任意（例: rehacalc連携）
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**
4. 「デプロイ」→ アクセス承認を求められたら自分のアカウントで許可
5. 表示された **ウェブアプリのURL**（`https://script.google.com/macros/s/.../exec`）をコピー

> 「アクセスできるユーザー: 全員」にしますが、URLを知っている人しかアクセスできません。
> さらに保護したい場合は `Code.gs` の `TOKEN` に任意の文字列を設定し、
> アプリ側の「DB連携設定」でも同じトークンを入力してください。

### 4. アプリに接続先を登録する

1. https://yamasa0601.github.io/rehacalc/evaluation.html を開く
2. 「DB送信」タブの「DB連携設定」ボタンを押し、コピーしたウェブアプリURLを貼り付ける
3. （TOKENを設定した場合のみ）続けて表示されるトークン欄にも同じ値を入力

設定はその端末のブラウザに保存されます。端末（iPad・PCなど）ごとに1回だけ必要です。

## 使い方

1. 「評価記録」タブでいつも通り入力（自動保存される）。対象者IDにはH番号（例: H001）を入力
2. 「DB送信」タブを開き、必要ならCCI・入棟日・SMI・歯の変数などのDB専用項目を入力
   （これらも対象者×評価時期ごとに自動保存されます）
3. 「整合性を確認して送信」ボタンを押す
4. ID⇔氏名の整合性チェックの結果が表示され、問題なければそのまま書き込まれる。
   「研究DBへ送信しました（〇行目に追記/上書き）」と表示されれば完了

## 転記される列の対応

| シート列 | アプリの入力欄 | 変換 |
|---|---|---|
| ID / name | 対象者ID / 氏名 | そのまま |
| 年齢 / 体重 | 年齢 / 体重 | そのまま |
| 身長 | 身長 (cm) | m に変換 |
| BMI | ― | 身長・体重から自動計算 |
| 性別 | 男 / 女 | m / f |
| 受傷日または手術日 | 受傷日（なければ手術日） | YYYY/MM/DD |
| 術側 | 右 / 左 | R / L |
| 術式 | 術式 | そのまま（THA/BHA/ORIF等を入力） |
| 歩行補助具 | 独歩/杖/4点杖/歩行器/その他 | Nouse/Tcane/Qcane/Walker/Other |
| 退院先 | 退院先 | そのまま |
| NRS | 歩行時NRS | そのまま |
| hip_flex 〜 nankle_dorsal_BW | HHD 6筋の右/左 | 術側→無印、非術側→n付き。_BW は N÷体重(kg) |
| BBS / MMSE / FAB / TMT_A / mFES | 各評価欄 | そのまま |
| 10mCWS / CWS_step | 10m快適速度 (m/s) / 歩数 | そのまま |
| time_point | 評価時期 | 入棟→admission、FAC3→FAC3、1M/2M/3M、退院→discharge |
| CCI / 回復期入棟日 / FAC3に至った日数 / 入院期間 / 退院日 | DB送信タブ | 日付は YYYY/MM/DD |
| R_TLA / L_TLA / R_LimbLength / L_LimbLength | DB送信タブ | そのまま |
| SMI / Pha / Alb | DB送信タブ | そのまま |
| natural_teeth / denture_use / denture_type | DB送信タブ（残存歯・入れ歯） | あり/なし・入れ歯あり/なし・総/部分/NA |

**注意**: 筋力（HHD）の列は術側/非術側に振り分けるため、「術側」が未選択だと送信されません。

## トラブルシューティング

- **「連携先が未設定です」** → 「DB連携設定」でウェブアプリURLを登録
- **「送信に失敗しました」** → デプロイ設定が「全員」になっているか確認。
  Code.gs を修正した場合は「デプロイ」→「デプロイを管理」→ 鉛筆 → バージョン「新規」で再デプロイ
- **行がずれて書き込まれた** → シートの列を並べ替えた場合は `Code.gs` の `COLUMNS` も同じ順に修正
